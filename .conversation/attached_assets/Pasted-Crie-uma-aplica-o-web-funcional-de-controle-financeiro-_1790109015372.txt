Crie uma aplicação web funcional de controle financeiro pessoal chamada provisoriamente "FinPro".

As duas imagens anexadas são a PRINCIPAL REFERÊNCIA VISUAL.

IMPORTANTE:
Não quero uma landing page nem apenas um mockup.
Quero uma aplicação funcional.

Toda a interface deve estar em português do Brasil.
Valores monetários devem usar o padrão brasileiro:
R$ 1.234,56.

========================
OBJETIVO DO MVP
========================

Nesta primeira etapa implemente SOMENTE:

1. Visão Geral / Dashboard
2. Transações
3. Cadastro de receitas e despesas
4. Edição e exclusão de transações
5. Categorias
6. Filtros
7. Gráficos
8. Persistência dos dados

Não implemente ainda:
- cartões de crédito
- contas bancárias
- parcelamentos
- recorrências
- relatórios avançados
- importação de arquivos
- integração bancária
- inteligência artificial

Essas funcionalidades serão adicionadas posteriormente.

Prefiro um MVP menor completamente funcional do que muitas funcionalidades incompletas.

========================
DESIGN
========================

Siga de perto as imagens anexadas.

Quero um dashboard financeiro premium em dark mode.

Identidade visual:

- fundo azul-marinho quase preto
- cards em azul-marinho escuro
- roxo/violeta como cor principal
- verde/esmeralda para receitas
- vermelho/rosa para despesas
- azul/ciano para informações secundárias
- bordas discretas
- cards arredondados
- sombras sutis
- tipografia moderna
- interface limpa
- boa densidade de informação

Evite:
- aparência genérica de template admin
- excesso de gradientes
- excesso de glow
- animações exageradas
- elementos gigantes

A aparência desktop deve ser bastante próxima das referências.

ARQUITETURA
========================

Utilize:

Utilize uma biblioteca adequada para os gráficos.

types
utils

========================
PERSISTÊNCIA
========================

Para esta primeira versão, escolha a solução de persistência gratuita e mais simples disponível no ambiente Replit.

A interface deve acessar os dados através de uma camada de serviço separada.

Não acople os componentes diretamente ao mecanismo de armazenamento.

Estruture de forma que posteriormente possamos migrar para PostgreSQL/Supabase sem reconstruir o frontend.

========================
VALORES MONETÁRIOS
========================

Evite erros de ponto flutuante em cálculos financeiros.

Internamente, prefira armazenar valores monetários em centavos inteiros.

Exemplo:

R$ 620,00 = 62000

Formate para BRL apenas na apresentação.
